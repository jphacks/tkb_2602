## 製品概要

### 背景(製品開発のきっかけ、課題等）
研究室には、誰の担当でもない雑務がたくさんあります。流しに残った洗い物、あふれたゴミ箱、つけっぱなしの電気、切れたままの消耗品。これらは「名もなき雑務」として、気づいた人が黙って片づけています。そして、片づけるのはいつも同じ人です。

この偏りを口にするのは、とても難しいことです。「また洗い物が残っていた」と言えば、「誰が残したのか」という話になります。言った人も言われた人も気まずくなるので、結局誰も言いません。片づける人は不満をためこみ、残す人は自分が残していることに気づかないままです。

既存のタスク管理ツールは、この問題に向いていません。担当者と期日を決めるのが基本だからです。名もなき雑務に担当者を決めれば、それは「やらなかった人を特定する仕組み」になり、責める相手を生みます。

私たちが解きたかったのは、**「誰も責めずに、問題が繰り返し起きていることだけを伝えるにはどうすればよいか」** という課題です。

### 製品説明（具体的な製品の説明）
やり残された雑務を、人ではなく **妖怪のしわざ** として扱う Discord ボットです。

1. やり残されていたことを見つけて片づけた人は、`/youkai` で「場所」と「やり残されていたこと」を選んで記録します（選ぶだけで、十数秒で終わります）。
2. 同じ場所で同じことが繰り返されると、本人にだけ見える返事の中で「気配」→「影」と変化し、決まった回数で **妖怪が出現** します。
3. 研究室の全員がいるチャンネルには、1日1回 **「妖怪だより」** が届きます。その日に出現した妖怪や成仏した妖怪を、名前と画像で伝えます。
4. 誰も記録しなくなれば（＝その雑務が起きなくなれば）、一定の日数がたったところで妖怪は **成仏** します。

妖怪は「繰り返し起きている問題そのもの」です。片づけるほど妖怪が育つのは、問題がまだ続いているからです。誰も片づけなくてよくなったとき、ようやく妖怪は姿を消します。

### 特長

#### 1. 誰も名指ししない —— 仕組みで守っている
「名前を出さないように気をつける」のではなく、**名前が出ようのない作り** にしています。

| 守っていること | 仕組み |
|---|---|
| 誰が記録したかを残さない | 記録の表（`reports`）には報告者の列がありません。守り神ポイントのためにだけ、Discord ID をそのまま使わず、秘密鍵で変換した値（HMAC-SHA256）を保存します（[report-session.ts](src/database/report-session.ts)） |
| 通知の時刻から推測させない | 全体への通知は、1日1回決まった時刻の「妖怪だより」だけです。記録した瞬間には何も流れないので、「さっき流しにいた人」が推測されません（[digest.ts](src/notifications/digest.ts)） |
| 自由記述から個人を特定させない | 「出っ歯」「隅っこ君」のようなあだ名は、その研究室の人にしか誰のことかわからず、AIでも見抜けません。そこで自由記述（ひとこと）は **公開しません**。管理者だけに、報告者の名前を付けずに届け、データベースにも保存しません（[youkai.ts](src/commands/youkai.ts)） |
| 公開する言葉は、あらかじめ決めたものだけ | 場所や雑務の名前は、管理者が登録した一覧から選びます。全体に流れる言葉は、この一覧と妖怪の名前だけです |
| 結果は本人にだけ見せる | 気配・影・出現の演出や守り神ポイントは、本人にだけ見える返事で出します |
| 書き込みで通知を飛ばさせない | ひとことに `@everyone` などが書かれていても、誰にも通知が飛ばないようにしています |

#### 2. 「繰り返し起きる問題」だけが妖怪になる
1回だけの出来事では、妖怪は生まれません。同じ場所で同じことが決まった回数くり返されたときだけ出現し、記録されるたびに育ちます（Lv.5・10・25 で姿が変わります）。最後の記録から一定の日数がたつと成仏します。「たまたま1回」と「ずっと続いている問題」を区別して見せられます。

#### 3. Discord だけで完結し、選ぶだけで記録できる
新しいアプリも Web ページも要りません。研究室がふだん使っている Discord の中で、`/youkai` からフォームを開き、選んで送るだけです。管理者は `/youkai-settei` で、場所や雑務の一覧、妖怪が出現する回数、妖怪だよりの時刻を設定できます。

### 解決出来ること
- 黙って片づけている人の負担を、**誰も責めずに** 研究室全体へ見えるようにできます。
- 「洗い物が残っている」と、角を立てずに伝えられます。伝えるのは人ではなく、妖怪だからです。
- 「どの場所で、何が繰り返し起きているか」がわかるので、置き場所を変える、当番を話し合うといった、仕組みでの解決につなげられます。

### 今後の展望
- 発表用の操作パネル `/demo`（時間を進める、妖怪だよりを今すぐ送る、リセット）
- 成仏の前に「弱ってきた」ことを妖怪だよりで知らせる
- 妖怪図鑑（出会った妖怪と、その個体の経歴）と、守り神（自分だけに見える成長）の表示
- 管理者が雑務を一覧に追加したとき、その研究室だけの新しい妖怪が生まれる仕組み

### 注力したこと（こだわり等）
* **「何を作らないか」を、名指ししないという軸で決めた**
  * **担当者と期日は作りません。** 担当を決めると「やらなかった人」が生まれ、責める仕組みになるからです。
  * **自由記述を、AIで妖怪の説明文や画像にする案はやめました。** あだ名などから個人が特定されうる道を、AIでは確実にふさげないためです。
  * **記録した瞬間に全体へ通知する案もやめました。** 通知の時刻から、誰が記録したかが推測できてしまうからです。
  * 迷ったときは、常に「この機能は、誰かを名指しする道を作らないか」で判断しました。
* **言葉づかい**：コマンドの言葉を「雑務を報告する」→「退治の記録」→「妖怪観測書」と見直しました。「報告」は苦情に、「退治」は記録するほど妖怪が育つルールと逆の意味に聞こえるからです。

## 開発技術
### 活用した技術
#### API・データ
* Discord API（スラッシュコマンド、モーダル、選択メニュー、本人にだけ見える返事）
* Supabase（PostgreSQL、RPC）

#### フレームワーク・ライブラリ・モジュール
* TypeScript、Node.js
* discord.js v14
* @supabase/supabase-js
* Node.js 標準の crypto（HMAC-SHA256）、node:test

#### デバイス
* なし（Discord が動くPC・スマートフォン）

### 独自技術
#### ハッカソンで開発した独自機能・技術
* **報告者を残さない記録処理**：記録・妖怪の状態の更新・守り神ポイント・妖怪だよりの予定の登録を、1回のデータベース関数（トランザクション）でまとめて行います。報告者はHMACで変換した値だけを扱います（[sql/functions/submit_report.sql](sql/functions/submit_report.sql)、[src/database/report-session.ts](src/database/report-session.ts)）
* **時刻を切り離した通知**：その日の出来事をためておき、決まった時刻に1通にまとめて送ります。送る直前に成仏を判定します（[src/notifications/digest.ts](src/notifications/digest.ts)、[sql/functions/process_yokai_ascensions.sql](sql/functions/process_yokai_ascensions.sql)）
* **モーダルの中の選択メニュー**：場所・やり残されていたこと・ひとことを、1枚のフォームでまとめて受け取ります。一覧はデータベースから毎回読み、Discord の3秒の制限内に開きます（[src/commands/youkai.ts](src/commands/youkai.ts)）
* **管理者用の設定画面**：場所や雑務の一覧を、消さずに「使わない」状態にして、これまでの記録とのつながりを残します（[src/commands/youkai-settei.ts](src/commands/youkai-settei.ts)、[sql/functions/save_guild_settings.sql](sql/functions/save_guild_settings.sql)）
* 妖怪と守り神のイラスト 65 枚は、Hack Day 前に生成AIで作成した素材です（[src/assets/](src/assets/)）
